# UI 响应式与全局告警设计

日期：2026-08-17

## 目标

修复两类已复现的界面问题：

1. 休息逾期时只有主时钟变色，时间轴、全屏控制条与页面背景仍保持普通状态，视觉割裂。
2. 横屏低高度视口中页面产生文档级滚动，用户无法在一屏内同时看到主时钟和完整时间轴。

修复后，正常、临近、到期和逾期状态使用同一套全局视觉变量；在 `1024×640`、`1280×720`、`1440×900` 横屏视口中不出现文档级滚动或内容遮挡。

## 当前证据

隔离 Playwright 环境实测：

| 视口 | `scrollHeight` | `clientHeight` | 超出 |
| --- | ---: | ---: | ---: |
| `1440×900` | 900 | 900 | 0 |
| `1280×720` | 783 | 720 | 63px |
| `1024×640` | 757 | 640 | 117px |
| `900×600` | 740 | 600 | 140px |

全屏逾期且展开时间轴时，`.clockface[data-away-level='3']` 为红色状态，`.timeline-drawer` 的计算背景仍为 `rgb(255, 255, 255)`。告警等级只存在于 `ClockFace`，`App` 和 `Timeline` 无法消费该状态。

## 参考实现

### Super Productivity

- 仓库：<https://github.com/super-productivity/super-productivity>
- 参考文件：`focus-mode-layout.component.scss`、`focus-mode-main.component.scss`、`focus-clock-face.component.scss`
- 采用机制：固定布局骨架，顶部控制脱离主内容流，上下保留等高槽位，主时钟尺寸由统一 CSS 变量派生。
- 解决对象：状态切换时的主时钟位移，低高度视口内容叠压。

### Pomotroid

- 仓库：<https://github.com/Splode/pomotroid>
- 参考文件：`src/app.css`、`src/lib/components/Timer.svelte`
- 采用机制：`html/body` 固定为视口高度并禁止页面级滚动；时钟、标签与控制组使用统一尺度和过渡 token。
- 解决对象：整页滚动、局部缩放不一致。

### FocusTide

- 仓库：<https://github.com/Hanziness/FocusTide>
- 参考文件：`layouts/timer.vue`、`components/timer/timerProgress.vue`、`assets/scss/transitions.scss`
- 采用机制：状态视觉作为全视口独立层，主内容与设置/任务层使用统一时长和缓动。
- 解决对象：告警只改变单个组件，页面状态不连续。

### Tomato

- 仓库：<https://github.com/nsh07/Tomato>
- 参考文件：`LastWeekScreen.kt` 及其 `currentWindowAdaptiveInfo` 用法
- 采用机制：依据窗口尺寸类别切换布局形态，主视图和统计视图各自使用合适的容器约束。
- 解决对象：单一宽度断点无法处理横屏低高度窗口。

本项目迁移上述机制和结构，不直接复制外部项目代码。

## 设计

### 1. 视口骨架

- `html`、`body`、`#root` 和 `.app` 统一使用 `100dvh`，页面级 `overflow: hidden`。
- 非全屏 `.app` 改为三行骨架：固定顶栏、`minmax(0, 1fr)` 主时钟、可控高度时间轴。
- 主时钟区允许缩小，但不允许溢出或将时间轴推出视口。
- 全屏时保留现有底部抽屉模式；抽屉打开后，主时钟根据抽屉真实高度上移，不使用固定 `-10vh` 假定。

### 2. 响应式尺度

- 建立一组由视口高度控制的 token：主区 padding、时钟 gap、主数字尺寸、科目控件尺寸、时间轴轨道高度。
- 宽度只负责横向容器和文字换行；高度负责竖向密度。
- 定义标准、紧凑、超紧凑三档高度类别，边界由现有组件最小可用尺寸和 E2E 测量固化，不在组件内分散硬编码。
- 核心内容不隐藏：时钟、科目、控制、休息状态、时间轴头、轨道、当日科目小计均保留。

### 3. 全局告警状态

- `ClockFace` 继续是休息等级的唯一计算者，不在 `App` 或 `Timeline` 重复休息算法。
- `.app` 通过已渲染的 `.clockface[data-away-level]` 消费状态，生成页面级状态 token。
- L1 只调整提示条和局部强调；L2 将温和琥珀色洗色扩展到主区与时间轴；L3 将红色洗色扩展到整个应用、时间轴、控制条和浮层边界。
- 告警背景使用一个全视口独立层进行呼吸，不分别让时钟和时间轴各自闪烁，避免频率不一致。
- 文字、科目色、时间轴片段色和当前时间 Flag 保持可读，告警色只作为背景氛围和边界强调。
- `prefers-reduced-motion` 或应用内关闭动画时，保留静态告警色和文案，停止呼吸动画。

### 4. 时间轴与历史回顾

- 普通当日时间轴使用骨架分配的固定高度，内部不产生竖向滚动。
- 7 天回顾打开时改用紧凑的汇总骨架，主时钟区同步收紧；7 条泳道、三个指标和科目汇总保持在当前视口中。
- 设置对话框、片段详情等独立浮层可在自身内部滚动，不得解锁文档级滚动。

### 5. 动效

- 使用项目已有 `motion` 和精确 CSS transition，不新增 GSAP 依赖。
- 可打断交互使用 transition；一次性入场和全局呼吸使用 keyframes。
- 页面级状态变化只过渡背景色、边界色、透明度和 transform，不使用 `transition: all`。
- 时间轴抽屉退出比进入更快，主时钟位移与抽屉使用同一缓动。

## 数据与状态边界

- 不修改 `shared/` 休息预算、静默时段、告警分级或计时状态机。
- 不修改 API、D1 schema、会话存储或幂等契约。
- 不从 UI 推断学习完成、掌握或健康数据。
- 告警状态仍只在空闲或暂停离开期间生效，专注运行中不进入休息提醒。

## 验收标准

### 自动化

1. `1024×640`、`1280×720`、`1440×900` 中，空闲、运行、暂停、结束反馈和 7 天回顾的 `scrollHeight <= clientHeight`。
2. 上述视口中无水平滚动，主时钟、主控制、休息状态和时间轴不重叠。
3. 全屏展开时间轴时，主时钟底部不进入抽屉范围，控制条不遮挡主时钟或时间轴头。
4. L3 状态下，应用根、主区、时间轴和全屏控制条共享同一告警状态 token；时间轴不再保持纯白/纯黑普通表面。
5. 动画关闭与 `prefers-reduced-motion` 下无持续动画，告警仍可识别。
6. 专注运行中 `data-away-level='0'`，不触发全局告警样式。

### 视觉验收

- 在浅色、深色和 reduced-motion 三种环境截图。
- 检查数字容器尺寸在秒数变化前后稳定。
- 检查文字不裁切、不遮挡，图标视觉居中，深浅色边界清晰。
- 检查逾期呼吸的主区与时间轴同步，频率与相位不分裂。

## 停止条件

- 上述自动化与视觉验收全部通过后完成。
- 若为满足 `1024×640` 必须隐藏核心内容、改变计时语义或修改 API，停止并重新评估布局。
